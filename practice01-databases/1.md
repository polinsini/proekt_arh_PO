# Контрольные вопросы

1. Что такое Docker-контейнер и чем он отличается от виртуальной машины?
Docker-контейнер — изолированная среда выполнения приложения, содержащая необходимые для его работы компоненты. В отличие от виртуальной машины, контейнер не содержит отдельную полноценную операционную систему и использует ядро ОС хоста. Это обеспечивает более быстрое создание и меньшие затраты ресурсов по сравнению с виртуальными машинами.

2. Для чего используется файл docker-compose.yml? Какие основные секции он содержит?

Файл docker-compose.yml предназначен для декларативного описания и запуска многоконтейнерного приложения. Основными секциями являются services для определения сервисов, volumes для постоянного хранения данных, а также параметры конфигурации сервисов, включая image, ports, environment, depends_on и healthcheck.

3. Зачем нужны тома (volumes) в Docker? Что произойдет с данными, если удалить контейнер без использования томов?

Docker volumes предназначены для постоянного хранения данных независимо от жизненного цикла контейнера. При удалении контейнера данные, хранящиеся только внутри файловой системы контейнера, будут удалены. При использовании именованного тома данные сохраняются после удаления контейнера. В методичке отдельно указано, что docker compose down сохраняет тома, а docker compose down -v удаляет их вместе с данными.

4. Что означает параметр depends_on в docker-compose? Гарантирует ли он, что зависимый сервис полностью готов к работе?

Параметр `depends_on` задаёт зависимость между сервисами и определяет порядок их запуска. Сам по себе `depends_on` не гарантирует полную готовность зависимого сервиса. Для ожидания фактической готовности необходимо использовать `healthcheck` совместно с условием `condition: service_healthy`. В представленной конфигурации Mongo Express и pgAdmin запускаются после прохождения проверки готовности соответствующей СУБД.

5. Назовите модель данных каждой из пяти СУБД. Для каких задач лучше подходит каждая из них?


* PostgreSQL — таблицы. Хорош для обычных приложений, финансовых систем и данных, где важны связи между таблицами.
* MongoDB — документы JSON/BSON. Хорош, когда структура данных гибкая.
* Redis — ключ → значение. Хорош для кэша, сессий, очередей и очень быстрых операций.
* Neo4j — граф: узлы + связи. Хорош для социальных сетей, рекомендаций и поиска связей.
* Elasticsearch — документы внутри индексов. Хорош для полнотекстового поиска, логов и аналитики.

| СУБД          | Модель данных         | Основные области применения                                                     |
| ------------- | --------------------- | ------------------------------------------------------------------------------- |
| PostgreSQL    | Реляционная           | Веб-приложения, финансовые системы, аналитика, ГИС                              |
| MongoDB       | Документная           | Веб- и мобильные приложения, IoT, системы управления контентом                  |
| Redis         | Ключ-значение         | Кэширование, очереди сообщений, пользовательские сессии, рейтинги, Pub/Sub      |
| Neo4j         | Графовая              | Социальные сети, рекомендательные системы, анализ мошенничества, сетевой анализ |
| Elasticsearch | Документная поисковая | Полнотекстовый поиск, логирование, мониторинг, аналитика                        |


6. Что такое ACID-транзакции? Какие из рассмотренных СУБД их поддерживают?


ACID — это набор правил, которые помогают базе нормально работать с важными операциями.

Например, мы переводим деньги: деньги должны либо полностью уйти от одного человека и прийти другому, либо операция вообще не должна произойти. Нельзя, чтобы деньги списались, но не пришли.

ACID означает:

* Atomicity — операция выполняется целиком или не выполняется вообще;
* Consistency — база после операции остаётся корректной;
* Isolation — параллельные операции не ломают друг друга;
* Durability — после подтверждения данные не должны потеряться.

В методичке прямо указано, что PostgreSQL поддерживает ACID-транзакции, а для Neo4j ACID-транзакции также указаны среди ключевых особенностей.  

7. Чем отличается тип поля text от keyword в Elasticsearch? Приведите примеры использования каждого.

Простыми словами:

`text` — для текста, который нужно искать по словам.

Например:

```text
"Я изучаю программирование на Python"
```

Если поле `text`, Elasticsearch может разбить эту строку на отдельные слова и искать документы по ним.

`keyword` — для точного значения целиком.

Например:

```text
"student"
```

Нам нужно найти именно значение `"student"`, а не искать отдельные слова внутри него.

Примеры:

```json
{
  "title": "Изучение программирования"
}
```

`title` → `text`.

```json
{
  "status": "completed"
}
```

`status` → `keyword`.



8. Что такое Cypher в Neo4j? Чем графовый запрос отличается от SQL-запроса при поиске связанных данных?


Cypher — это язык, на котором мы разговариваем с Neo4j.

В обычной SQL-базе мы думаем таблицами:

```text
users
friends
```

и соединяем их через `JOIN`.

В Neo4j мы думаем графом:

```text
Полина → дружит → Маша → дружит → Катя
```

И можно прямо сказать: «Найди друзей моих друзей».

То есть SQL обычно работает с таблицами и соединяет их, а Cypher непосредственно описывает узлы и связи между ними.

Cypher — декларативный язык запросов графовой СУБД Neo4j. В отличие от SQL, ориентированного преимущественно на работу с реляционными таблицами и операциями соединения, Cypher использует графовую модель и позволяет непосредственно описывать узлы, связи и пути между ними. 

9. Почему Redis хранит данные в оперативной памяти? Какие механизмы персистентности он поддерживает?

Оперативная память намного быстрее диска. Поэтому Redis держит данные в RAM и благодаря этому работает очень быстро.

Но возникает проблема: если компьютер выключить, оперативная память очищается.

Поэтому Redis умеет сохранять данные на диск. В нашей методичке указаны два механизма:

* RDB — периодические снимки данных;
* AOF — запись операций, которые изменяют данные.


10. Что такое healthcheck в Docker Compose? Почему его важно настраивать?

`healthcheck` — это проверка: «Сервис действительно работает или контейнер просто запущен?»

Контейнер может иметь статус `Up`, но база внутри него ещё может запускаться.

Например:

```text
PostgreSQL контейнер запущен
↓
PostgreSQL ещё загружается
↓
pgAdmin пытается подключиться
↓
ошибка
```

С `healthcheck` Docker может дождаться состояния `healthy`.

11. Объясните разницу между командами docker compose stop и docker compose down. Когда следует использовать каждую?


`stop` — просто выключить контейнеры.

```bash
docker compose stop
```

Контейнеры останутся, поэтому потом можно сделать:

```bash
docker compose start
```

и продолжить работу.

`down` — убрать контейнеры из Docker.

```bash
docker compose down
```

Контейнеры удалятся, но volumes по умолчанию останутся.

Если сделать:

```bash
docker compose down -v
```

удалятся ещё и volumes, а значит можно потерять данные баз данных.


12. Какие стратегии перезапуска (restart policy) существуют в Docker? Чем unless-stopped отличается от always?

Docker предоставляет политики автоматического перезапуска `no`, `on-failure`, `always` и `unless-stopped`. Политика `always` предусматривает автоматический перезапуск контейнера независимо от причины остановки. Политика `unless-stopped` также автоматически перезапускает контейнер, однако не запускает его повторно после явной остановки пользователем.

13. Зачем ограничивать потребление памяти для Elasticsearch и Neo4j (параметры JVM heap)? Что произойдет, если этого не сделать?

Ограничение JVM heap необходимо для контроля потребления оперативной памяти Elasticsearch и Neo4j. Без ограничения данные приложения могут потреблять значительный объём памяти, что способно привести к дефициту RAM, снижению производительности, завершению процессов и невозможности корректной работы других контейнеров. В конфигурации Elasticsearch из практической работы размер heap установлен равным 512 МБ, а общий лимит памяти контейнера — 1 ГБ. 

14. Сравните веб-интерфейсы всех пяти СУБД. Какой из них, по вашему мнению, наиболее функциональный и почему?

У нас используются такие интерфейсы:

* Redis → Redis Commander;
* MongoDB → Mongo Express;
* Neo4j → Neo4j Browser;
* Elasticsearch → Kibana;
* PostgreSQL → pgAdmin 4.

Они отличаются задачами. Redis Commander нужен для просмотра ключей, Mongo Express — для документов MongoDB, Neo4j Browser позволяет работать с графом и визуализировать связи, Kibana предназначена для работы с Elasticsearch, поиска, аналитики и визуализации, а pgAdmin позволяет управлять PostgreSQL и выполнять SQL.

15. Какие потенциальные проблемы безопасности существуют в представленных конфигурациях? Что нужно изменить для production-окружения?

В методичке настройки сделаны для учебы, поэтому безопасность специально упрощена.

Например, пароли очень простые:

```text
secret
admin
mypassword
mysecretpassword
```

У Elasticsearch вообще отключена защита:

```yaml
xpack.security.enabled=false
```

То есть это нормально для локальной лабораторной работы, но для реального сервера так делать нельзя.

Для production нужно:

* использовать сложные уникальные пароли;
* не хранить пароли прямо в `docker-compose.yml`;
* использовать secrets или защищённые переменные окружения;
* включить SSL/TLS;
* включить аутентификацию и авторизацию;
* не открывать наружу порты, которые не нужны;
* ограничить доступ к базам через сеть/firewall;
* регулярно обновлять Docker-образы;
* делать резервное копирование;
* не использовать `latest`, а фиксировать версии образов;
* ограничивать права пользователей.
